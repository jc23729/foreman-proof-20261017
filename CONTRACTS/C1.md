# C1 — JSON output for `report_cli.py`

Add a `--json` flag to `report_cli.py`.

## Behaviour

`python3 report_cli.py --input tests/fixtures/jobs.json --json` must print
exactly one JSON object on stdout and nothing else:

```json
{"total": 4, "done": 1, "running": 0, "queued": 2, "blocked": 1, "next_queued": "J-02"}
```

Keys are exactly `total`, `done`, `running`, `queued`, `blocked`,
`next_queued`. `next_queued` is the id string of the highest-priority queued
job, or `null` when there are no queued jobs. Key order does not matter; the
object is compared after parsing.

Exit code 0 on success. On invalid input: non-zero exit, a short message on
stderr, and nothing on stdout.

Default behaviour (no `--json`) must not change.

## Acceptance

- `tests/test_report_json.py` — new behaviour
- `tests/test_report_cli.py` — regression, existing text output

## Constraints

- Only `report_cli.py` may change. `job_report.py` must stay byte-identical.
- No new third-party dependencies.
- No file writes at runtime.
